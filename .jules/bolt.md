## 2026-08-02 - [Memoize list rendering in App Rooms]
**Learning:** React re-renders components frequently during state updates or navigation. Large list rendering (e.g. 35 `MealCard` instances in `CalendarRoom`) or heavy mapping/filtering of data (e.g. `MEALS.filter` in `ChainsRoom` and `KitchenRoom`) causes unnecessary garbage collection and main thread blockages when parent components re-render without the underlying data actually changing.
**Action:** Applied `React.memo` to complex stateless list items (`MealCard`, `ChainConnectors`) and `useMemo` for derived dataset computations in heavy view components to avoid O(N) redundant calculations on simple state changes. Next time, preemptively memoize expensive derivations based on global constants that are manipulated locally.
## 2026-08-04 - [Optimize Spread component re-renders]
**Learning:** In list rendering components like `ChainsView` that map over a dataset and pass global state down to complex item components like `Spread`, React's default behavior is to re-render all instances whenever the parent's state changes. When components take callback functions like `isCooked` as props, standard `React.memo` isn't enough because the function reference might change or its returned value for a specific item might change.
**Action:** When memoizing list components that depend on derived global state or callback functions, provide a custom `arePropsEqual` function to `React.memo()`. This custom function should check if the specific list item is affected by the state change (e.g., checking if the item's ID is the one that was selected or marked cooked). This prevents severe main thread blockages caused by O(N) redundant re-renders upon simple parent state changes.
