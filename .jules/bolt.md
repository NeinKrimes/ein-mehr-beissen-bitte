## 2026-07-30 - [Extract Clock to reduce re-renders]\n**Learning:** The `useClock` hook triggered a re-render of the entire `App` component and all of its heavy children (`BoardRoom`, `CalendarRoom`, etc.) every 30 seconds due to `setNow` updating the state at the root level.\n**Action:** Extracted the hook into its own isolated `<Clock />` component to contain the frequent timer-based state updates, preventing expensive global re-renders. Next time, always check if periodic state updates can be isolated to a small child component.
## 2026-07-31 - [Optimize getPalateKey execution]\n**Learning:** The `getRecipe` function within `useRecipe` is called frequently during rendering loops (such as aggregating recipes for the `ShoppingList` component). Deriving a cache key using expensive array operations (spreads, sorts, joins) on the `palate` object inside these callbacks causes significant redundant computation and garbage collection pressure.\n**Action:** Memoize derived keys using `useMemo` and depend on the primitive result string, drastically reducing redundant operations when object dependencies haven't changed.
## 2026-08-02 - [Memoize list rendering in App Rooms]
**Learning:** React re-renders components frequently during state updates or navigation. Large list rendering (e.g. 35 `MealCard` instances in `CalendarRoom`) or heavy mapping/filtering of data (e.g. `MEALS.filter` in `ChainsRoom` and `KitchenRoom`) causes unnecessary garbage collection and main thread blockages when parent components re-render without the underlying data actually changing.
**Action:** Applied `React.memo` to complex stateless list items (`MealCard`, `ChainConnectors`) and `useMemo` for derived dataset computations in heavy view components to avoid O(N) redundant calculations on simple state changes. Next time, preemptively memoize expensive derivations based on global constants that are manipulated locally.
## 2026-08-11 - [Optimize ChainsView re-renders]
**Learning:** `Spread` components in `ChainsView` are rendered inside a map loop, and any state change in `ChainsView` (like selecting a different meal) triggers a re-render of all 10 `Spread` instances, which each run heavy array computations (maps, reduces, filters) on their chains.
**Action:** Wrapped `Spread` in `React.memo` to prevent unnecessary re-renders of all chains when only one changes. Also identified that fixing the flaky test in `useLibraryBasket` requires increasing the `waitFor` timeout since it relies on resolving a large lazy-loaded chunk.
